## Commands

All commands are server-side only and check the player's role/permissions server-side.

### Elite admin commands

Every command below is **restricted** — it does nothing until the calling player
holds the matching ACE permission (see [Granting yourself admin](#granting-yourself-admin)).

They also hand the flashdisk or tablet to **the player who ran them**, so they must
be typed in-game. Running them from the server console creates the database rows
with no item to show for it.

| Command | Effect |
|---------|--------|
| `/generate_elite_flashdisk [id] [name] [pin]` | Creates the Elite org and hands you its flashdisk. `id` is the internal org id, `name` is what shows at login, `pin` must be at least 4 characters. |
| `/create_seller [org_id] [name] [pin]` | Creates a seller org. Does **not** hand out a flashdisk — use `/generate_seller_flashdisk` after. |
| `/create_buyer [org_id] [name] [pin]` | Creates a buyer org, same as above. |
| `/generate_seller_flashdisk [org_id]` | Hands you a flashdisk for an existing seller org, to pass on in character. |
| `/generate_buyer_flashdisk [org_id]` | Same, for a buyer org. |
| `/regenerate_elite_flashdisk [org_id]` | Issues a replacement Elite flashdisk. Use when the original is lost or was never received. |
| `/create_item [item_id] [name] [label] [price] [category]` | Adds an item to the catalog. Easier to do from Elite Desktop, which has a searchable item picker. |
| `/list_sellers` / `/list_buyers` / `/list_items` | Prints the org and catalog ids, for when you need one for another command. |
| `/give_tablet [player_id]` | Gives the tablet item. Defaults to yourself when no id is passed. |

Arguments are split on spaces, so keep a `name` to a single word unless you are
sure your server build accepts quoted arguments.

### Granting yourself admin

Add to `server.cfg`, then restart:

```cfg
add_ace group.dnd_admin command.generate_elite_flashdisk allow
add_ace group.dnd_admin command.generate_seller_flashdisk allow
add_ace group.dnd_admin command.generate_buyer_flashdisk allow
add_ace group.dnd_admin command.regenerate_elite_flashdisk allow
add_ace group.dnd_admin command.create_seller allow
add_ace group.dnd_admin command.create_buyer allow
add_ace group.dnd_admin command.create_item allow
add_ace group.dnd_admin command.list_sellers allow
add_ace group.dnd_admin command.list_buyers allow
add_ace group.dnd_admin command.list_items allow
add_ace group.dnd_admin command.give_tablet allow
add_ace group.dnd_admin command.test_tablet allow

add_principal identifier.steam:XXXXXXXXXXXXXXXXX group.dnd_admin
```

### First-time setup

1. Grant yourself the ACE permissions above and restart the server.
2. In-game, run `/generate_elite_flashdisk highTable "High Table" 1234` — you receive the flashdisk item.
3. Use the flashdisk from your inventory and enter the PIN to open Elite Desktop.
4. Add items to the catalog, then create seller and buyer orgs and hand out their flashdisks in character.

## NUI actions (Lua callbacks)

The frontend sends actions to the server via `TriggerServerEvent('dnd_blackmarket:nuiCallback', action, data)`. Server validates everything before returning.

### Authentication

| Action | Parameters | Returns | Notes |
|--------|-----------|---------|-------|
| `validateFlashdisk` | `orgId, orgType, flashdiskKey` | Validation result | Called on terminal/laptop access |
| `authenticateUser` | `pin` | Auth success + session token | PIN-based login |

### Elite dashboard

| Action | Parameters | Returns | Notes |
|--------|-----------|---------|-------|
| `elite_getSellers` | — | List of all sellers | — |
| `elite_getBuyers` | — | List of all buyers | — |
| `elite_getItems` | — | Item catalog | — |
| `elite_createItem` | Item data | `{success, itemId}` | — |
| `elite_grantPermission` | `sellerId, [...itemIds]` | `{success}` | Seller can now list item |
| `elite_suspendSeller` | `sellerId` | `{success}` | Disable seller access |
| `elite_generateFlashdisk` | `orgId, role, pin, name` | `{success, flashdiskKey}` | — |

### Seller orders

| Action | Parameters | Returns | Notes |
|--------|-----------|---------|-------|
| `seller_getOrders` | — | List of orders for this seller | — |
| `acceptOrder` | `orderId` | `{success}` | Change status to `approved` |
| `rejectOrder` | `orderId` | `{success}` | Change status to `declined` |
| `readyToDeliver` | `orderId` | `{success}` | Change status to `ready_to_deliver` |

### Buyer shopping

### Courier

| Action | Parameters | Returns | Notes |
|--------|-----------|---------|-------|

## Exports

The resource exposes some functions for integration with other resources.

### Darkchat exports (for dnd_phone)

```lua
-- Get all identities for a player (seller, buyer, courier, elite)
local identities = exports.dnd_blackmarketplace:darkchat_getIdentities(source)

-- Verify PIN for an org
local ok = exports.dnd_blackmarketplace:darkchat_verifyPin(orgId, orgType, pin)

-- Get list of chat partners for this org
local partners = exports.dnd_blackmarketplace:darkchat_getChatOrgs(orgId, orgType)
```

| Event | Data | Notes |
|-------|------|-------|
| `dnd_blackmarket:orderCreated` | `{orderId, sellerId, buyerId}` | New order created |
| `dnd_blackmarket:orderAccepted` | `{orderId}` | Seller accepted |
| `dnd_blackmarket:orderCompleted` | `{orderId, total}` | Payment settled |
| `dnd_blackmarket:ratingSubmitted` | `{orderId, buyerId, rating}` | After completion window |
| `dnd_blackmarket:deliveryStarted` | `{orderId, courierId}` | Courier en route |

## Error codes

Common errors returned by callbacks:

| Error | Cause |
|-------|-------|
| `Access denied` | Server session doesn't match the required role |
| `Order not found` | Order ID doesn't exist or is invalid |
| `Insufficient funds` | Buyer doesn't have enough cash/bank balance |
| `Invalid PIN` | PIN didn't match the hashed value |
| `Already rated` | Buyer already submitted a rating for this order |
| `Dispute already filed` | Only one dispute per order allowed |

## Troubleshooting

**"Buyer is not online"** — Order completion requires the buyer to be online (or at least carrying their flashdisk). This is intentional to prevent free goods. Wait for them to log in.

**"Order is not in a completable status"** — Order must be `approved`, `ready_to_deliver`, or `on_the_way` before marking complete. Seller must accept and mark it ready first.

**"Payment failed"** — Check `Config.useBank` and whether Renewed-Banking is running. Verify buyer's bank account is set if using bank mode.

**NUI won't open** — Verify the flashdisk exists in inventory, PIN is correct, and the org is marked `is_active = 1` in the database.
